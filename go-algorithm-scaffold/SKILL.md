# Go 算法题测试框架

根据用户给出的题目，生成一份可以复制到本地运行的完整 Go 代码，让用户自行实现解题函数。

## 输出要求

默认直接输出一个完整的 Go 代码块，包含：

1. `package main`。
2. 实际需要的标准库导入。
3. `main` 中的表驱动测试用例。
4. 遍历用例、调用解题函数、判断结果并打印中文测试信息。
5. 待实现的解题函数。

保留用户提供的函数名称、参数和返回值类型。没有函数签名时，根据题意拟定合适的签名。

默认不用 ACM 输入输出模式，不读取标准输入，不使用 `testing` 包。

除非用户要求，不给出解题思路、算法提示或完整实现。

## 待实现函数

函数内保留：

```go
// 在这里实现
```

添加必要的占位返回值，使整份代码能够编译运行，例如：

- `int`：`return 0`，无解约定为 `-1` 时也可使用 `return -1`。
- `bool`：`return false`。
- `string`：`return ""`。
- 切片、指针：`return nil`。
- 多返回值：返回对应类型的占位值。

占位返回值仅用于运行框架，不代表正确答案。不要为了让测试通过而填写解题逻辑。

## 测试用例设计

按照题目约束选择有代表性的测试，通常包含：

- 普通情况与题目示例。
- 最小合法输入。
- 重复元素、零、负数等题目允许的情况。
- 无解、多解、全部满足或全部不满足的情况。
- 容易暴露边界错误的情况。

不必机械地覆盖所有类别，不生成违反题目约束的输入。例如题目明确要求数组非空时，不强行添加空数组。

为有唯一预期结果的题目填写 `want`，逐一核对期望值。不能把未经核实的结果作为标准答案。

## 结果比较

根据返回类型选择比较方式：

- 数字、布尔值和字符串：直接使用 `==`。
- 一维切片：使用 `slices.Equal` 或合适的比较函数。
- 多维切片：根据题意使用 `reflect.DeepEqual` 或自定义比较函数。
- 无顺序要求的结果：在副本上规范化顺序，再比较。
- 多种合法答案的题目：验证答案是否合法，而不是强制与某个固定答案相同。

规范化时不要去重，以免掩盖用户代码生成重复答案的问题。区分外层结果无序与内部元素顺序有意义的情况，不能随意排序内部元素。

对 N 皇后等要求返回全部方案的题目，可结合已知方案数量、每个方案的合法性和方案不重复来验证。

测试框架应允许合理的空结果表示；题意不区分时，不因 `nil` 切片与空切片的区别判错。

## 特殊数据结构

链表和二叉树题目需要补齐节点类型，以及必要的构建、转换或验证辅助函数。

辅助函数只服务于测试，不实现题目的核心算法。

检查链表输出时防止因用户代码产生环而无限遍历。

如果解题函数可能修改输入，复制测试数据后再调用。二维切片、链表和树等按需要进行深拷贝，避免影响预期结果和后续测试。

## 打印格式

每个用例应显示：

- 用例序号。
- 输入。
- 实际结果。
- 期望结果，或合法性验证结果。
- 是否通过。

字符串使用 `%q`，切片通常使用 `%v`。

示例：

```go
for i, tc := range tests {
    got := strStr(tc.text, tc.pattern)
    fmt.Printf(
        "用例%d：text=%q pattern=%q，结果=%d，期望=%d，通过=%t\n",
        i+1, tc.text, tc.pattern,
        got, tc.want, got == tc.want,
    )
}
```

## 题意不完整时

优先使用当前对话已经明确的规则。

如果缺失条件会改变预期结果，例如是否允许负数、是否保持原顺序、无解时返回什么，简短说明采用的练习约定；无法合理确定时，只询问必要条件。

不要把自行补充的练习规则说成原题规则。

## 文件操作

默认在聊天中提供代码。只有用户要求保存到本地时，才创建或修改代码文件，并遵循用户指定的路径。

只有实际执行过编译或运行，才能说明已编译或已运行；不要把代码审查描述为运行验证。
